# Simple timeline + full theming (light/dark/system + custom accent)

Two features, one pass:

## A. Simple timeline (default) for normal users

**Preference**: new store field `timelineDetail: 'simple' | 'detailed'` (default **simple**), persisted to localStorage `agentdeck-timeline-detail` (same pattern as `starred`), with a `setTimelineDetail` action. Read directly by `Timeline`/`Turn`/`Step`/part components via `useStore` so all three Timeline surfaces (mobile, desktop, right-rail threads) follow automatically.

**Simple mode hides / softens (all existing single-condition hides):**
- Token chips on the Reasoning row (chat.tsx:250-265), the whole `TurnSummary`+`UsageMeter` footer stats row (Timeline.tsx:253-261)
- Tool durations, `+N` diffstats, exit codes (chat.tsx Step), ToolGroup "N steps · 1.2s" footer (keep just a status dot)
- Raw JSON/args expansion + hover chevron (Step 412-425); ToolGroups render always-collapsed with a friendly one-line label ("Edited 3 files" / "Working…")
- `ContextChip`, `config_changed` rows, verification command/output detail, git-commit shas, browser-row mono action/status
- Keep: user bubbles, prose + code, approvals, plan card, error cards, file chips (collapsed to "N files changed"), activity line, queue UI

**Toggle**: icon button (List/Eye-style) in the desktop TopBar and the mobile session header — one tap flips simple/detailed everywhere.

## B. Theme system

**Mechanism**: `data-theme="dark|light"` on `<html>` + CSS var overrides; custom accent via runtime `setProperty` on the `--accent*` family. No Tailwind rebuild needed.

1. **`lib/theme.ts`** — `ThemeMode = 'system' | 'dark' | 'light'`, `applyTheme(mode, accentHex?)`: resolves system via `matchMedia('(prefers-color-scheme: dark)')` (listener while in system mode), sets `data-theme`, derives `--accent-hover/-ink/-tint/-2` from a custom accent (darken/contrast math), updates `<meta name="theme-color">` to the resolved canvas. Persists `agentdeck-theme` + `agentdeck-accent`; dispatches an `agentdeck-theme-change` event.
2. **FOUC guard** — tiny inline `<script>` in `index.html` head that reads the two localStorage keys and sets `data-theme`/accent vars before first paint.
3. **`index.css`**:
   - `:root` stays the current dark palette; add a full `[data-theme='light']` override block (warm paper palette: light canvas/surfaces, dark ink, same accent system, light-appropriate shadows/status tints).
   - Var-ize the hardcoded bits: body::before grain, `::selection`.
   - Scoped utility overrides for the most common literal utilities that break light mode (`text-white`, `text-black`, `bg-white/[0.04–0.1]`, `border-white/[0.06–0.14]`, `bg-black/20–70` etc.) — one centralized `[data-theme='light'] .text-white {…}` block covers all call sites without touching hundreds of files.
4. **Tailwind config** — convert the hardcoded `zinc/emerald/amber/orange/red/sky` ramps to `tone()` var mappings (new `--zinc-1..6` etc. defined per theme) so the hundreds of existing `text-zinc-*` classes flip with the theme.
5. **Hardcoded hex cleanup** — replace raw `#191613 / #141210 / #241f1a / #2a241e / #211d19` literals with token classes in the visible surfaces: App.tsx, chat.tsx, Composer.tsx, StationHome, HomeSidebar, LeftSidebar, RightRail, GitWorkspaceView, SettingsSection. (RoomAvatars gradients & agent-hue arrays stay — identity colors are fine on both themes.)
6. **Terminal** — TerminalView's xterm theme object reads from `getComputedStyle` at mount and re-reads on `agentdeck-theme-change` (dark keeps current palette; light gets a light terminal pair via `--term-bg/--term-fg`).
7. **Settings UI** — new "Appearance" section in SettingsSection: mode segmented control (System / Light / Dark) + accent swatches (current amber + blue/green/violet/rose) + custom hex input, saving via `lib/theme.ts`.

**Known debt accepted in v1**: remaining `bg-white/x`-style literals beyond the override list (less-trafficked screens), manifest `theme_color` (static; iOS PWA chrome updates only on reinstall), and any straggler hexes in minor components — noted for a follow-up pass.
