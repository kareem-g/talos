## 1. New AI-event parts

### 1.1 Frontend types (`dashboard/src/types/conversation.ts`)
Add to `MessagePart`:
- `SubagentPart { kind:'subagent'; id; name; kindType; status:'running'|'completed'|'failed'; startedAt }`
- `ProgressPart { kind:'progress'; percent?; message?; step? }`
- `SearchPart { kind:'search'; query; results?: string[] }`
- `GitCommitPart { kind:'git_commit'; sha; message; files?: string[] }`
- `ConfigChangedPart { kind:'config_changed'; key; value }`

### 1.2 Reducer (`dashboard/src/lib/events.ts`)
Map event kinds → parts:
- `subagent_started` → push `SubagentPart(running)`
- `subagent_finished` → update matching `SubagentPart` by id
- `progress` → push `ProgressPart`
- `search_started` / `search_result` → push `SearchPart`
- `git_commit` → push `GitCommitPart`
- `mode_changed` → keep existing mode state **and** push `ConfigChangedPart`

### 1.3 Views / adapters (`workspaceData.ts`, `chat.tsx`, `RightRailViews.tsx`)
- `deriveAgentActivity`: emit activity for the new parts (subagent/progress/search/git).
- `tasksFromEvents`: also treat `SubagentPart` as an in-progress step (real work item).
- Timeline `Part` (`components/chat.tsx`): render `progress` (bar + %), `subagent` (chip/status), `search` (query row), `git_commit`, `config_changed` rows.
- Agents tab: read `SubagentPart`s from the transcript (in addition to derived) + render live `ProgressPart`.

### 1.4 Backend event sources (best-effort, per protocol)
- **ACP** (`backend/src/agents/acp.rs`): if the ACP sessionUpdate carries `task`/`subagent`/`progress`/`search` shapes, forward them as `subagent_started|finished`, `progress`, `search_started`. (The `plan` mapping already exists.)
- **Claude stream-json** (`backend/src/agents/claude_stream.rs`): forward `task`/`progress` hooks when Claude emits them (`/task`, `/progress`).
- Unknown event kinds remain safely ignored by the frontend.

## 4. Custom `/` commands: `/side` and `/btw`
- New **side-session tab type** in the right panel: `rightTabs.ts` adds `side`.
  - `SideSessionView`: a mini chat (transcript + composer) bound to a chosen "side" session, sharing the current project context.
- `/side <prompt>` (composer): creates a new session (same agent/project), opens it in the right panel as the `side` tab, sends the prompt, and lets the user keep chatting there — the side session is a full conversation, independent but same project/context.
- `/btw <message>` (composer): sends a message to the currently-open side session (creates one if none). A quick "by the way" note that lands in the side chat without disturbing the main thread.
- Implementation:
  - Composer slash menu: add built-in commands `side` and `btw` (agent-agnostic; not provider-specific).
  - On send, detect leading `/side` / `/btw`, parse the rest, call the store/API to create/send to the side session, and open the right-panel `side` tab (via `RightRail` imperative `openTab('side')`).
  - RightRail: `SideSessionView` holds the active side-session id (localStorage-persisted), renders its conversation + a composer that calls `sendPrompt(sideSessionId, …)`.
- Keyboard/UX: keep `Ctrl+Shift+…` shortcuts; tab strip shows `Side` tab with a live badge.
